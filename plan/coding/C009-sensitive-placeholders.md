# C009 · 敏感信息用占位符记在本地，填表时由系统换成真实值

**状态：并入 [C014](C014-move-forward.md)（用户定下，2026-10-24）**：占位符写成 `{KEY}`，真实值在 `storage/settings/personal.env`。下面是原来的草稿。

- 依据：用户（2026-10-23，真实跑通小米 Agent工程师后，[C006-fix-real-run](C006-fix-real-run.md) 第 7 条）：年龄、身份证、籍贯、居住地点这类敏感信息也希望记在本地 memory 里，投递时自动填；每次投递确认前和 Agent 对话，Agent 按对话更新 Session / Project 的资料。
- 现状：
  - 证件号码、签证和工作授权、薪资、民族、宗教、健康、犯罪记录、声明承诺是 C 级：不提取、不写入任何文件（memory.md「新建 Project」第 5 条、资料字段 `class: A | B`），申请 Agent 不填（`FieldClassGuard` 拒绝，`SnapshotRedactor` 遮值），交给用户在浏览器里亲填（workflow.md 关卡 B「用户已填」、agent-runtime.md 第 7 节）。
  - 年龄 / 出生日期、籍贯、居住地点现在**不是** C 级：资料里有就按 A / B 级填，没有就问用户。这几项不需要占位符，只要资料里有；本计划主要针对 C 级里用户愿意自动填的那几项（身份证号等）。

## 设计（短）

1. **资料里只存占位符**：Project / 全局资料里，C 级字段的值写成 `${ID_NUMBER}` 这样的占位符（键名由用户定），分级仍标 C。模型、上下文、日志、报告、运行记录只会看到占位符。
2. **真实值在用户自己维护的本地密钥文件**：例如 `storage/settings/.env`（或单独的 `storage/settings/personal.env`），和模型 API key 同一种做法：代理不读、不改，用户手动写；程序运行时读。
3. **填表那一刻替换**：申请 Agent 照常 `browser_fill_form` / `browser_type`，值写占位符（`fact` 写资料键）。系统在把调用发给 Playwright MCP 之前，把占位符换成真实值；工具结果、快照（`SnapshotRedactor` 继续遮值）、run log、填写报告里仍只有占位符（报告来源写「资料（本地密钥）」）。
4. **守卫的变化**：`FieldClassGuard` 从「C 级一律拒绝」改为「C 级只接受占位符」：值是资料里登记过的占位符就放行替换；是明文就照旧拒绝、交给用户。没有登记占位符的 C 级字段（签证、薪资、声明承诺等）照旧交给用户亲填。
5. **投递前对话更新资料**：每次投递确认前（对话 Agent 排简历、定下用哪份的那一步），对话 Agent 可以按用户的话更新这个 Project / Session 的资料（新增或改 A / B 级事实；C 级只登记占位符的键，提醒用户去本地密钥文件里写值）。写入仍走「候选 → 确认 → 写入」。

## 会改动的地方（确认后再细化）

- `dev-limit.md`：新增一条边界，写明 C 级可以「占位符进资料、真实值在用户维护的本地密钥文件、系统只在发给浏览器时替换」，并沿用密钥文件的规则（代理不读不改、日志不出现值）。
- `plan/master/memory.md`：「C 级不允许出现在任何文件里」改为「C 级只允许以占位符出现」；字段分级加 C（占位符）。
- `plan/master/workflow.md`：主流程「C 级字段 → 用户亲填」、关卡 B 报告的写法；第 5 条「发给模型供应商的个人信息」——C 级仍不发给模型（只发占位符）。
- `plan/master/agent-runtime.md` 第 7 节：C 级字段的守卫说明。
- 代码（大致）：资料解析允许 C 级占位符；`FieldClassGuard` 放行登记过的占位符；浏览器调用发出前替换；本地密钥文件的读取（复用读 `.env` 的那一套）。提示词：资料里有占位符的 C 级字段直接填占位符，其余照旧交给用户。

## 影响的边界和风险

- 真实值会经过本机进程内存和 Playwright MCP 发到页面；不进模型供应商、不进日志和报告。
- 用户需要自己维护密钥文件；值写错时页面上填的就是错的，报告里只看得到占位符，要用户在浏览器里核对。
- 快照里页面回显的真实值靠 `SnapshotRedactor` 遮掉；遮不住的格式（例如分成几格的证件号）会被模型看到，确认前要定是否可以接受。

## 怎么确认能用（确认后）

- `mvn -B clean verify` 通过。
- 本机真实跑一次：资料里登记 `${ID_NUMBER}`，本地文件写值，申请时页面上填进真实值；run log、报告、发给模型的消息里只有占位符。
