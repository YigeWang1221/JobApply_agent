# C005 · 前端界面（和 C005 调研 Agent 一起做）

- 依据：[ui.md「界面结构」](../../master/ui.md)、示意页（虚构数据）https://claude.ai/artifact/4K6eE85i51GvrLUGz8cARD 的样式；[agent-runtime.md 第 7 节](../../master/agent-runtime.md)（申请 Agent）；[C005-research-agent.md](C005-research-agent.md)（对话 Agent）。
- 目标：把现在的调试标签页换成真正的应用：左边 Project / Session 侧栏，右边按选中的内容切换。用户能在界面里完成「新建 Session → 和 Agent 聊、调研出候选 → 选岗位开始申请 → 在申请工作台里回应 Agent → 停在提交前审阅」。
- 不做：全局漏斗、时间线、每周节奏、复盘题库（里程碑第 6 段）；登录账号、多用户、部署。不写前端测试。

## 样式

照示意页：浅色暖灰底（`--bg #f4f4f1`）、白色面板、细边框、8px 圆角；IBM Plex Sans + 中文系统字体；主色蓝 `#2a6fc4`；深色模式跟随系统。颜色全部用 CSS 变量，放在一个样式文件里。不引入 UI 组件库。

## 页面

| 选中 | 主区域 | 数据来源 |
| --- | --- | --- |
| 侧栏 | 品牌、「全局」、Projects（每个下面列它的 Session，最近的在上）、设置 | `GET /api/projects` |
| 全局 | 所有 Project 的 KPI 一行（投递、准备中、等你、停在提交前…）+ 每个 Project 一张卡片 | 同上 |
| Project | 顶部「新建 Session」；KPI；**候选池**（按公司分组：岗位、城市、类型、状态，操作「想投 / 不投 / 开始申请」）；**申请**（转为申请的 Job 和它的 prep 状态）；最近的 Session 和交接摘要 | `GET /api/projects/{id}` |
| Session | **对话视图**：消息流、输入框、Agent 正在做什么（调了哪个工具）；右侧是这个 Session 涉及的岗位 | C005-research-agent |
| Job | **申请工作台**：顶部岗位信息和状态；左边是 Agent 每一步做了什么（对话里的工具调用和说明，取自 `runs/<job-id>.json` 和过程日志）和计划；右边是「现在要你做的事」（Agent 的话、问题、选文件、回复框）、停止按钮；停在提交前时显示填写报告 | `GET /api/jobs/{id}`、申请接口 |
| 设置 | 模型（现有设置页）、资料（现有的原件、来源、导入、资料页并到这里，作为子标签） | 现有接口 |

现在的「申请」调试页删掉，功能并进 Job 页。

## 后端要补的只读接口

- `GET /api/projects`：每个 Project 的 id、名字、Session 列表（id、标题、时间、摘要）、Job 计数。
- `GET /api/projects/{id}`：Project 信息、全部 Job（候选和申请，带 lead_status / phase / prep_state / 申请线程状态）、最近的 Session。
- `GET /api/jobs/{id}`：岗位信息、状态、事件、申请线程的对话步骤（只给工具名、说明、给用户的话，不给快照）。
- 候选池操作走 C005-research-agent 的接口（改 lead_status、开始申请）。
- 施工时补的缺口（2026-10-23）：storage 里还没有 Project，界面没法开始；补 `POST /api/projects`（id + 名字，继承 base、跟随最新），侧栏有「新建 Project」。「开始申请」可以直接对候选点：后端先转为申请再开始。
- 前后端共用的接口形状在施工时定下，写在本文件「实际结果」里。

## 怎么确认能用

- `npm run build`、`mvn -B clean verify` 通过。
- 用户在本机打开前端，走一遍：新建 Session → 让 Agent 找岗位 → 候选池里出现结果 → 开始申请一个夹具岗位 → 在工作台里回复 → 看到填写报告。

## 实际结果

- 施工（2026-10-23，并行代理）：`App.tsx`（侧栏 + 按 `location.hash` 切换）、`route.ts`、`status.tsx`、`pages/Global`、`ProjectPage`、`SessionPage`、`JobPage`（原「申请」页的回复、问题、上传、报告组件搬进来）、`Settings`（模型 / 资料子标签）；`styles.css` 按示意页重写；`pages/Application.tsx` 删除。
- 接口（后端 `api/ProjectController`、`SessionController`、`JobController`、`Views`）：`GET/POST /api/projects`、`GET /api/projects/{id}`、`POST /api/projects/{id}/sessions`、`GET /api/sessions/{id}`、`POST /api/sessions/{id}/messages`、`/stop`、`GET /api/jobs/{id}`、`PATCH /api/jobs/{id}/lead`（记在发现它的 Session 下，状态机不允许时 409）。对话消息里工具调用折叠成「名字 · 说明 → 结果首行」，给模型的系统说明不返回。
- 验证：`npm run build`、`mvn -B clean verify` 通过。用户在浏览器里走一遍：用户 2026-10-23 执行，报告没有问题。
- 已知问题：「Agent 正在用…」取对话里最后一个工具，可能慢一步。
