# C006-front · 对话界面重做：照 ChatGPT / Claude 的对话 Agent 界面

- 依据：用户反馈（2026-10-23）：C005 界面不好看、不实用；工具调用和思考过程没有展开列表，回复没有渲染。参考 ChatGPT、Claude.ai、Claude Code / Cursor 的 Agent 面板、Perplexity 的来源展示。
- 目标：Session 对话页和申请工作台看起来、用起来像成熟的 AI 对话产品：回复按 Markdown 渲染，思考和每一步工具调用都能展开看，正在做什么一眼看得到。
- 不做：删除对话、编辑已发的消息（改名由用户追加，见「追加」）；后端要补的数据（思考内容、完整工具结果、流式输出），这些放在 C006-agent；在它们到之前，前端用现有字段显示，字段到了自动显示完整内容。不写前端测试。

## 现在的问题（读 C005 代码确认过）

- 回复是纯文本，换行、列表、链接、表格都没有渲染。
- 一条回复的所有工具调用收进一个 `<details>`，每步只有一行「名字 · 说明 → 结果首行」，看不到参数和结果内容。
- 没有思考过程（后端也没给）。
- 「Agent 正在用…」取对话里最后一个工具，慢一步；每 2 秒轮询，没有逐字输出。
- 输入框、空状态、消息操作（复制、重试）都很简陋；对话不会自动滚到底。

## 怎么做（参考的样子）

**消息流**（Claude.ai / ChatGPT）
- 用户消息靠右的浅色气泡；Agent 回复不加气泡，全宽排版，阅读宽度约 720px 居中。
- 回复按 Markdown 渲染：标题、列表、表格、代码块（等宽 + 复制按钮）、链接新标签页打开。
- 每条回复下方悬停出现操作：复制、时间；（最后一条）重新生成等 C006-agent 给接口后再接。
- 新消息到来时自动滚到底；用户往上翻时不强制滚动，显示「回到底部」按钮。

**过程展开列表**（Claude 的 thinking 块、Claude Code / Cursor 的工具卡片）
- 每轮回复上方是一条可折叠的「过程」：默认折叠，标题是一句摘要（「搜索了 3 次，读了 2 个页面，加了 1 个候选 · 用时 40 秒」）；运行中默认展开、实时追加。
- 展开后按时间排列：
  - **思考**：灰色斜体段落，长的折叠成前 3 行，可展开。
  - **工具调用**：一行一张小卡片：图标（搜索 / 网页 / 浏览器 / 候选池 / skill / 问用户）+ 动作说明（「搜索：后端 校招 上海」「读取：jobs.example.com/123」）+ 状态（进行中转圈 / 完成 / 失败 / 被拒绝）。点开看参数和结果：搜索结果列成带标题和网址的链接列表；网页结果显示前几段 + 「全文在 cache/web/…」；被拒绝的显示原因。
  - **读 skill**：显示 skill 名字，点开看正文。
- 来源（Perplexity）：本轮读过的网页在回复末尾列成一行小标签，点开新标签页。

**正在做什么**
- 运行中在消息流底部显示一行状态：正在思考 / 正在搜索「…」/ 正在 Chrome 里读 …，带计时；旁边是停止按钮。

**输入框**（Claude.ai）
- 底部固定，圆角卡片；文本框随内容长高（最多约 8 行）；Enter 发送、Shift+Enter 换行、输入法组字时 Enter 不发送。
- 运行中发送按钮变成停止。
- 空 Session 显示几条建议（「按我的简历撒网找岗位」「核验候选池里没核验的」「投想投的那几个」），点了直接发。

**结构化卡片**
- `add_lead` / `update_lead` 的结果在过程里显示成小岗位卡（公司、岗位、城市、状态），点了打开 Job 页。
- `ask_user` 显示成醒目的提问块，下面就是输入框。

**布局**
- 侧栏：可收起；Project 下的 Session 列表显示运行中的小圆点；当前项高亮。
- Session 页：中间对话，右侧岗位面板可收起；窄屏时右侧面板变成顶部的按钮弹出。
- 申请工作台用同一套消息流和过程列表显示申请 Agent 的每一步；右侧仍是「现在要你做的事」。

**视觉**：保留 C005 的颜色变量和深色模式；字号、行距、留白按 Claude.ai 调（正文 15px、行高 1.65）；图标用内联 SVG，不加图标库。

## 依赖（用户确认，2026-10-23）

- `react-markdown` + `remark-gfm`：渲染 Markdown（表格、删除线、任务列表）。不加 UI 组件库、不加代码高亮库（代码块先只用等宽字体）。版本施工时按当时稳定版定，写进本文件。

## 和 C006-agent 的接口约定

前端按下面的字段写，后端没给时降级显示：

- 每条 assistant 消息里的 `steps`（按时间排列，替代现在的 `tools`）：`{ kind: "thinking" | "tool", text?, name?, summary?, args?, result?, status: "running" | "done" | "failed" | "rejected", startedAt?, endedAt? }`。没有 `steps` 时用现有 `tools` 拼出来。
- 会话的 `activity`：`{ kind: "thinking" | "tool", name?, summary?, since }`，表示现在在做什么；没有时退回 `lastTool`。
- 流式：有 SSE 接口时用它追加步骤和活动，没有时照旧 2 秒轮询。
- 思考只在 `steps` 里真的有 `thinking` 时显示，前端不推测、不补。
- `sessions[].status`（侧栏运行中标记）、重新生成接口：有了再接。

## 怎么确认能用

- `npm run build` 通过。
- 用户在本机浏览器里看：一段带列表、表格、链接的回复渲染正确；展开过程能看到每次搜索的结果和读过的网页；运行中能看到当前在做什么并能停止；申请工作台的步骤也能展开。

## 实际结果

施工：2026-10-23。依赖：`react-markdown` 10.1.0、`remark-gfm` 4.0.1，没有加别的。

- 新目录 `frontend/src/chat/`：`MessageList`（消息流、自动滚动、「回到底部」、运行状态行和计时、出错重试、重新生成）、`ProcessBlock`（过程折叠块、思考、工具卡片、岗位卡）、`process.ts`（把消息拼成一轮、工具说明、摘要、来源、搜索 / 网页结果解析）、`Markdown`、`Composer`、`CopyButton`、`ChatSkeleton`、`icons`（内联 SVG）、`useLiveUpdates`（SSE，连不上退回 2 秒轮询）。`frontend/src/toast.tsx`：轻提示。
- Session 页重写：整屏高度、720px 居中、底部固定输入框、乐观显示用户消息（失败标红可重发）、按 Session 存草稿（localStorage，存不了就跳过）、空对话三条建议、`interrupted` 显示错误和重试（重发上一条用户消息）、`document.title` 用对话名、右侧岗位面板可收起（窄于 1100px 变成顶部按钮弹出）。
- 申请工作台的步骤改用同一个 `MessageList`（不带输入框和重新生成，状态行旁有停止）；走 `/api/jobs/{id}/events`。
- 侧栏：顶部「新对话」（调已有的 `POST /api/projects/{id}/sessions`，Project 取当前页所在的，否则第一个）、Session 按今天 / 昨天 / 更早分组、可收起成图标栏（记在 localStorage）、`status` 为 running / interrupted 时显示小圆点。
- 候选池「不投」改成行内输入原因；标记和开始申请成功后给轻提示。
- 模型设置：不显示「显示思考」开关（C006-agent 核实 Spring AI 2.0.1 不能在工具调用多轮里把 Anthropic 思考原样发回，按计划「不开这个开关，并在设置页写明」），只在用途分配下写一段说明：OpenAI 兼容推理模型返回思考时自动显示，Anthropic 暂不开启。
- 降级：没有 `steps` 时用 `tools` 拼（状态按结果是否以「失败」「被拒绝」开头判断，只有结果首行）；没有 `activity` 时取最后一轮里还没结果的工具，否则「正在思考」；岗位卡没有参数时从结果里取 Job 编号、从岗位列表里查公司和岗位；`ask_user` 拿不到原话时整条回复显示成提问块；用时取步骤时间，没有时用消息时间。
- 删掉 `status.tsx` 里旧的 `ChatLog` / `lastTool` 和 `styles.css` 里旧的对话样式；颜色变量和深色模式不变。
- `vite.config.ts` 未改：开发代理直接转发 SSE。
- 验证：`npm run build` 通过（与 C006-agent 合并后重跑）。浏览器里看效果：未运行，等用户。
