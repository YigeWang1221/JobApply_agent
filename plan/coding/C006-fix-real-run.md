## 修了什么（2026-10-23）

- **第 8 条**：申请 Agent 新控制工具 `read_resume(file)`，读「可上传的文件」里第几个文件的文字（和对话 Agent 的 `read_resume` 共用 `ResumeMatch.fileText` → `AssetAnalyzer.text`，C 级的值已去掉，最多 12000 字）。没有 `resume_choice` 时，用户在上传位置选的文件也在这张单子里，一样能读。开场在定了简历时写「填项目、实习、教育和描述之前先 read_resume 读文件 1」。
- **第 1 条**：见 [C008-fix](C008-fix-resume-confirm.md)。
- **第 2、4、6 条**：`ApplyAgent` 提示词新增「折叠和可展开的区域」「简历原文」「教育、实习、工作、项目」「原文和措辞」「拿不准写什么、写不写、怎么写」五条，原来的「项目和经历：用资料里的原文，不改写、不扩写」改为「资料 / 简历原文优先，字数限制时只裁剪，不编造；描述框不以附件里有为由留空」。skill apply-form 新增「折叠区域和经历条目」「上传和值的来源」两节。
- **第 3 条**：提示词「上传」改为解析结束后把自动填进来的每一个值和资料、简历原文核对；「值的来源」：`fact` 写资料键 / ans-NNN / `resume` / none，页面自动解析核对过没改的字段在 finish 的 summary 里单独列。代码只加一处：`fact: resume` 的字段在报告里来源写「简历原文」（`FillReportWriter.RESUME_SOURCE`，用 `Recorded` 行）。skill resume-parse 加两条（没动过的自动填值也核对；解析常漏项目条目）。
- 预置 skill 只在 `storage/playbook/skills/` 里缺文件时补，已有的不覆盖：本机已有的 apply-form、resume-parse 要用户删掉旧文件（下次启动补新的）才拿到新正文；提示词里已经写了同样的要点。
