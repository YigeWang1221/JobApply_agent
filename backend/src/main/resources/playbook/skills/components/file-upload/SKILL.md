# 文件上传

## 流程

- **先看「可上传的文件」清单**：
  - 清单里已经有合适的文件（例如用户在对话里定好的简历，开场会说明是文件 1），**直接调用 `browser_file_upload` 上传，不再用 `ask_user` 问用户**。
  - 页面上有必填的上传位置（如成绩单、作品集、证明材料），而「可上传的文件」清单里还没有对应的文件时，才用 `ask_user` 的 `files` 参数把上传位置列出来请用户选择。
- **首选上传方式（带 `target`）**：调用 `browser_file_upload` 时带上 `target`（上传按钮或上传区域的 ref，如「上传简历」「选择文件」「Upload」）和 `files`（文件编号数组，如 `[1]`）。系统直接把等字节文件副本设到该控件的 `<input type=file>` 上，不需要先点按钮、也不需要弹出文件选择窗口；即使按钮被遮罩盖住或 `<input type=file>` 是隐藏的也能直接传上。
- **备选方式（文件选择窗口已打开）**：如果先点了上传按钮，浏览器已经打开了文件选择窗口（快照里显示 `[File chooser]`），调用 `browser_file_upload`（不带 `target`）把文件交给它。窗口开着时别的操作都会报 `does not handle the modal state`，要先处理这个窗口。
- 点击报 `Timeout … exceeded` 是动作超时（元素被遮罩盖住或不可见），不是浏览器的安全限制，不要编造「浏览器安全限制需要用户手点」；直接用带 `target` 的 `browser_file_upload` 即可。
- 上传的文件是系统从原件准备的等字节副本，原件的内容和排版不修改，也不转换格式。

## 经验

- 发出上传调用只代表文件交给了页面，不代表上传完成。要等「上传中」「Uploading」、进度条或转圈消失（可用 `browser_wait_for`），再看快照的附件列表里有没有出现这份文件名。
- 回读每份附件：文件名、大小（如果显示）、完成状态，以及有没有「上传失败」「格式不支持」「文件过大」一类的提示。
- 有的附件栏一条只能挂一个文件：多份文件（作品集、成绩单、证书）要先点「添加」新增条目，再逐个上传、逐个核对。
- 同一个页面可能有好几个上传位置（简历、作品集、其他附件），按区域标题区分，不按出现顺序猜。
- 上传简历往往会触发自动解析，解析会回填并覆盖已填的字段（见 `resume-parse`）。有简历解析的页面，应当先上传简历、等解析结束，再核对和补全其它字段。
- 刷新或翻页后附件可能丢失；保存后回读时要连附件一起看。
- 文件格式和大小限制通常写在上传位置旁边（例如只收 PDF、不超过 10MB）。不符合时用 `ask_user` 告诉用户，不自行转换或压缩文件。
- 替换已上传的文件时，先删掉旧的条目（小叉或「删除」按钮），看快照确认旧文件不在了，再上传新的。
