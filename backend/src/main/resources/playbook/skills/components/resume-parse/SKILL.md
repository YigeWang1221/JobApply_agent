# 简历解析之后的校正

## 发生了什么

- 很多申请系统在上传主简历后自动解析，把识别出的内容回填到表单：联系方式、教育经历、工作经历、项目、技能。
- 回填会覆盖已经填好的字段，也可能新增或合并不完整的经历卡片。所以顺序是：先上传简历 → 等解析结束（「解析中」「Parsing」消失，或页面提示解析完成）→ 取新快照并用 `update_state` 更新这一页的字段清单 → 逐项核对和校正。
- 解析结束的信号因站点而异：提示条、弹窗（「是否用解析结果填充」）、字段突然有了值。弹窗里的选择（覆盖 / 不覆盖）要看说明文字；拿不准时问用户。

## 常见的解析错误

- **学校与专业**：同名或名称相近的学校被识别成另一所（例如识别成另一个城市或国家的同名学校），学校所在城市或专业大类识别错。
- **联系方式與地点**：国际区号识别错，区号和号码被拆错；「所在地点」「籍贯」「期望城市」被解析器从简历里的学校或实习城市瞎猜了一个填进去。
- **日期**：开始或结束日期偏移一天或一个月，年月顺序颠倒，「至今」没有识别。
- **经历条目**：某一段项目或实习经历整段遗漏；两段经历被合成一段；描述被截断或丢了换行；超链接丢失。
- **学位与学历**：旧版的学位名称或简历里的其它写法被带进来，和下拉选项不一致。
- **语言**：中文简历的字段被填进英文表单（或反过来），需要按表单的语言取资料里对应语言的写法。

## 经验

- 解析出错的原因通常查不清。校正时直接把字段改成资料或 `read_resume` 简历原文里的值，不在资料之外推算（例如不自行加减日期去「抵消」偏移）。
- **没动过的自动解析字段也要核对**：解析自动填进来、你没有亲手改过的字段，也要和有效资料、简历原文逐个核对。核对无误的在 `update_state` 里记成 `verified`（`note` 标明页面自动解析并已核对），并在 `finish` 的 `summary` 里单独列出；不一致的直接改掉，拿不准的用 `ask_user` 问用户。
- **逐段对照经历**：对照 `read_resume` 的简历原文数一遍教育、实习、项目各有几段；解析漏掉的条目点「添加」补全（见 `repeatable-entries`），被截断的描述用简历原文补全；解析多出来的、资料和简历里都没有的段落，问用户是否删除，不自行删。
- 有「同步更新在线简历」「用解析结果更新我的资料」一类的选项时，是否勾选或关闭看用户说明；拿不准时问用户。
- 校正完保存，再回读一次：有的站点在保存或翻页时会再触发一次解析，把校正过的字段改回去。
