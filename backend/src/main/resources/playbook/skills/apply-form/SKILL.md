# 在线申请表的通用经验

本 skill 是陈述句的经验，不是命令。每一条都要按当前页面核对；页面和经验不一致时，以页面为准。
申请工作台采用「两阶段闭环」：若上下文「可上传的文件」里还没有选定的简历，先调 `read_jd`、`list_resumes`、`read_resume(key)` 在工作台里输出简历匹配排名表与针对本岗位 JD 的修改建议，请用户确认后调 `choose_resume` 将选定简历设为「文件 1」，再打开岗位页面进入填表阶段。

## 读快照

- 快照是无障碍树：每个可操作的元素带一个 ref、角色（textbox、combobox、button、link、checkbox、radio 等）和名字。只有最新快照里出现过的 ref 才能用。
- 页面一变（翻页、弹窗、展开一个区域、上传完成后重新渲染），旧的 ref 就失效。写操作之后系统会重新取一次快照，下一步应当看新快照，而不是沿用旧 ref。
- 点开下拉、级联、日期面板之后，系统给的快照可能只有「弹出层」那一块（开头有说明）：上一份整页快照还留在对话里，那份快照里的 ref 仍然能用；它之后页面上别的变化（之前还开着的弹出层、输入框里新键入的字）不在里面，要看时直接用 browser_snapshot 取整页，不用为此按 Escape。
- 字段的名字有时在元素自己身上，有时在它前面的文本或分组标题里。同名的输入框（例如每段教育经历里都有一个「开始时间」）要按所在区域区分，不按出现顺序猜。
- 必填项通常带星号、「必填」或 required 字样；校验错误通常是字段附近的红字。快照里看不到颜色，只能看文字。
- 快照很长时，先找页面结构：进度条或步骤条（「第 2/4 步」）、区域标题（基本信息、教育经历、工作经历、附件、其他问题）、底部的按钮区。
- 看到「Sign in」「登录」字样不一定表示已经退出，要看页头的账户状态（头像、名字、「我的投递」「退出登录」）。

## 多页表单

- 很多申请表分成几步：基本信息 → 教育 / 经历 → 附件 → 附加问题 → 预览。步骤条或进度条是判断「这是第几步、还剩几步」的主要依据。
- 有的站点「在线简历」和「岗位申请」是两件事：在线简历保存成功，并不代表某个岗位已经申请；反过来，申请时也可能直接用在线简历里的内容。两者要分别核对。
- 翻到下一页之前，当前页的必填项要填完，否则按钮可能没有反应，或者页面停在原地显示错误。停在原地时先读错误提示，不重复点击。
- 最后一步通常叫「预览」「确认信息」「Review」。到了这一步，下一个按钮多半就是提交类按钮，本系统不点它，由用户自己点。

## 资料与表单的映射、批量填写

- 一页里能确定答案的字段一次填完，再统一核对，比一个字段一轮更省步骤。
- 下拉、级联用 browser_select_option，日期用 browser_set_date，一个控件一次调用（见 readonly-select、cascader-city、date-picker）。browser_fill_form 里只读的框和自定义下拉会被跳过，结果里写明哪些没填、为什么，其余照常填。
- **扁平资料 → 层级与分类控件**：资料常只记叶子值（如所在地/籍贯只写「台州」、专业写「软件工程」），而表单可能要求选多级路径（「国家 → 省 → 市」）或所属大类（「学科门类 → 专业类」）。客观的上下级或大类归属由你自己按常识补全（例如传 `["中国", "浙江", "台州"]`，或从第 1 层返回的省份/大类选项里直接选出归属项），不为客观归属停下来问用户；只有主观意愿（意向城市、是否服从调剂）或资料里没有的更细层级（具体区县/街道）才用 ask_user 问用户。
- 选项题要看实际选项：写法不同但意思一致的直接选；确实没有语义一致或客观归属关系的选项时，把选项原文列给用户选，不硬选一个相近的。
- 敏感或法律类字段（证件、工作授权、签证担保、人口统计、健康、薪资期望、法律声明）：资料里有 C 级占位符 `{KEY}` 就填占位符，没有就交给用户亲填。
- 单次申请里的答案只属于这一次申请，不当作以后的默认值。
- 用户接手过的页面，交回后先只读一次当前状态，不覆盖用户填的内容。

## 折叠区域和经历条目

- 项目经历、实习、作品、获奖、语言能力、自我评价这类区域常常是折叠的，或者只露出「添加」「展开」「+」「编辑」。没点开之前看不到里面有没有必填项，也看不到解析是不是已经填进去了。每个这样的区域都要点开看一次。
- 教育、实习、工作、项目按简历逐条填：简历里有几段就添加几段，每段的名称、角色、起止时间、描述都填。只填了一段、缺起止时间、描述空着，都算没填完。
- 填经历之前先读简历原文（`read_resume`）。有效资料是从事实整理出来的，常常没有每段经历的完整描述；简历原文里有。
- 标题、公司、项目名和专有名词照资料 / 简历原文写。简历是英文的就填英文，不自己翻成中文；页面有字数限制时只裁剪。
- 表单里有描述框时就要填，「附件简历里已经有」不是留空的理由：很多招聘系统筛选时只看表单字段。
- 拿不准写什么、写不写、怎么写时，攒起来一次问用户，不自己决定留空。

## 上传和值的来源

- 工作台阶段一经用户确认并调用 `choose_resume` 后，选定的简历已自动放进「可上传的文件」成为「文件 1」（或在开始前已选定为文件 1）。到简历上传位置直接用 `browser_file_upload`（带 `target` 和 `files: [1]`）上传，不再问用户；缺少其它附件时才用 `ask_user` 的 `files` 请用户选。
- 上传后页面自动解析填进去的值，和自己填的一样要回读核对，见 resume-parse。
- 每个值都说得出来源：资料、本次答案、简历原文、页面自动解析。报告里写明；页面自动解析、核对过没改的字段在总结里单独列出。

## 保存并回读

- 「输入成功」「点了选项」不等于「已保存」。保存后要重新读页面（刷新或重新进入这一步），确认值还在。
- 下拉框显示了选中值、但字段旁边仍有必填错误时，常见原因是没有触发失焦校验；聚焦这个字段后按 Tab 往往能消掉错误。提交按钮不是校验工具。
- 刷新后附件可能丢失，回读时要连附件一起看：文件名、大小、完成状态。
- 操作超时后，先读当前 URL 和主内容，判断操作是否实际成功，再决定下一步；盲目重复可能重复添加条目。
- 点击、输入、选择超时时，系统会检查一次原因写进错误：元素可不可见、在不在屏幕里、中心那一点被哪个元素盖住（以及它所在的 fixed / sticky 层）、是不是只读 / 禁用 / 原生下拉，还有哪些弹出层开着。点击的目标只是被盖住时，系统已经在这个元素上直接点了一次，结果里会写明，要看新快照核对是不是真的生效。
- 照检查结果处理：目标是只读的框，键入不会生效，日期用 browser_set_date、下拉用 browser_select_option；弹出层开着时，要选里面的项就直接点，要关掉按一次 Escape 或点一下空白处，不反复按；被底部操作栏、顶部导航这类固定栏挡住，滚动让它到屏幕中间再点；不可见的元素先展开它所在的区域。不要自己编原因（「没有 tabindex」「需要真实用户触发」「浏览器安全限制」）。都试过还不行，再问用户，说清是哪个元素、被什么盖住。

## 按钮的用途怎么判断（软边界的依据）

- 名字里带提交类词的按钮（提交、投递、申请、递交、发送、Submit、Apply、Send、Finish 等，包括「保存并提交」「确认提交」这种组合）是硬边界：系统一律不点，由用户自己点。岗位详情页上进入申请表的「立即申请」也算在内。对话框里问「确认提交 / 确定投递吗？」的那个「确定」「确认」「OK」也是硬边界。这一条写在代码里，skill 和站点记录都改变不了它。
- 「下一步、继续、下一页、保存、暂存、存草稿、Next、Continue、Save」，以及对话框、卡片、日期面板、级联里的「确定、确认、完成、Confirm、Done、OK」是软边界：点之前要说明用途（下一步 / 保存草稿 / 确认 / 拿不准）、是否像是最后一步（`final_step_suspected`），以及依据。
- 常见的依据：
  - 步骤条或进度条的位置。在「第 2/4 步」上点「下一步」，通常只是翻页；在最后一步上点「继续」，可能就是提交。
  - 按钮旁边的说明文字，例如「保存后可以继续修改」「提交后不可修改」。
  - 页面上是否还有一个单独的提交类按钮。同一页上同时有「保存」和「提交」时，「保存」通常只是暂存。
  - 页面标题或区域标题是否是「预览」「确认信息」「Review」。在预览页上，任何往前走的按钮都要当成可能提交。
- 拿不准、像是最后一步（或者同一页还有提交类按钮、步骤条已到最后一步）时，先用 ask_user 问用户这一个按钮；用户的批准只对当前这一页上的这个按钮生效一次，不记入站点长期放行。
- 不能用点击来试探一个按钮是不是只进入详情或预览：有的入口点一下就直接完成了申请。

## 停止写操作的信号

- 出现验证码、滑块、「请完成安全验证」一类的提示时，提交请求可能已经发出。立即停止写操作，交给用户；用户完成后只读核对，绝不重试。
- 页面出现「投递成功」「申请已提交」「Application submitted」「Thank you for applying」一类的文字时，停止写操作，只读核对。
- 页面弹出网页对话框（alert、confirm）时，不替用户选择，交给用户。

## 其它

- 同名链接、加号按钮（「添加教育经历」「+」）要限定在对应区域里找，不用全页的第几个去猜位置。点了添加要看快照确认真的多了一张卡片；当前卡片常常要先保存。详见 skill repeatable-entries。
- 报元素不可见或不在可视区域时，先滚动到它所在的区域。
- 用户和系统不要同时操作同一个表单；用户在编辑、上传或切换标签页时，系统不做写操作。
- 标签页：`browser_tabs list` 列出用户 Chrome 里所有的标签页，标出你的和别的任务在用的。标着「别的任务在用」的页不要碰（别的申请同时在用同一个 Chrome）；用户自己开着的页，用户让你用时再用（按标题和网址找到它，`browser_tabs select` 过去）。
